# Lesson 25 値とポインタ

Python の `id()` に相当するものは Go になく、「配列や構造体は値としてコピー、スライスとマップは中身を共有」という区別で考えます。最後に `&` と `*` のポインタで、関数から呼び出し元の変数を変える方法を学びます。

## ch01 値型のコピー（int・struct・配列は代入で複製）

Python ではすべての変数がオブジェクトへの参照で、`id()` で同一性を確かめられましたが、Go に `id()` はありません。代わりに「型ごとのコピーのされ方」で考えます。`int`・構造体・配列（固定長）は**値型**（代入や引数渡しで中身が丸ごと複製される型）です。コピーを書き換えても元の変数は変わりません。配列が値としてコピーされる点は、Python のリストとの大きな違いです。🟡 「代入=複製」になる型を押さえましょう。

Python ではこう書いた:

```python
a = [1, 2, 3]
b = a       # 同じオブジェクトを指す
b[0] = 100  # a も変わる
```

Go ではこう書く:

```go
a := [3]int{1, 2, 3} // 配列は値型
b := a               // 中身が丸ごとコピーされる
b[0] = 100           // a は変わらない
```

## ch02 スライスとマップが「参照的」に振る舞う理由

スライスの実体は「配列へのポインタ・長さ・容量」を持つ小さな**ヘッダ**です。代入でコピーされるのはこのヘッダだけで、中身の配列は共有されたままです。そのため片方の要素を変えると、もう片方からも変わって見えます。マップも同様に内部データへの参照を持ちます。Python のリストや辞書の共有と同じ見た目ですが、Go では「同じ配列を指しているから」と理由まで説明できます。🟡 ヘッダと配列の関係を理解しましょう。

Python ではこう書いた:

```python
a = [1, 2, 3]
b = a       # 同じリストを指す
b[0] = 100  # a も [100, 2, 3]
```

Go ではこう書く:

```go
a := []int{1, 2, 3}
b := a     // ヘッダのコピー。中身の配列は同じ
b[0] = 100 // a も [100 2 3] になる
```

## ch03 ポインタ（& と * で呼び出し元を変える）

**ポインタ**は変数のメモリ上の場所を指す値です。`&x` で x のポインタを取り、`*p` で指し先の値を読み書きします（デリファレンスと呼びます）。Go の引数は常に値渡しでコピーされるため、関数の中から呼び出し元の変数を書き換えたいときはポインタを渡します。Python では引数への再代入は呼び出し元に届きませんでしたが、Go はポインタで「届かせる」ことを明示できます。🟡 & と * の役割を理解しましょう。

Python ではこう書いた:

```python
def add_ten(n):
    n += 10  # 呼び出し元の変数は変わらない
```

Go ではこう書く:

```go
func addTen(p *int) {
	*p += 10 // 指し先を書き換える → 呼び出し元が変わる
}

addTen(&x)
```
