# Lesson 19 変数のスコープ

Go の変数は `{}` 単位のブロックスコープで、`global` / `nonlocal` はありません。`if v, err := ...` の `:=` が作る意図しないシャドーイングが実務の落とし穴です。

## ch01 ブロックスコープ {}

変数が使える範囲を**スコープ**といいます。Go の変数は、宣言した `{}`（ブロック）の中だけで有効です。Python では if や for の中で作った変数を外でも使えましたが、Go では for や if の中で宣言した変数はブロックを出ると消え、外で使うとコンパイルエラーになります。ループの結果を外に残したいときは、**ブロックの外で先に宣言**してから中で代入します。🟡 「宣言した場所で寿命が決まる」という理屈を理解しましょう。

Python ではこう書いた:

```python
if x > 0:
    msg = "plus"
print(msg)  # if の外でも使える
```

Go ではこう書く:

```go
msg := "" // 外で使いたい変数は外で宣言する
if x > 0 {
	msg = "plus"
}
fmt.Println(msg)
```

## ch02 シャドーイング

内側のブロックで外側と**同じ名前**の変数を `:=` で宣言すると、内側ではその新しい変数が外側の変数を隠します。これを**シャドーイング**といいます。外側の変数が消えるわけではなく、ブロックを出ると元の値のまま戻ってきます。Python では関数の中のローカル変数が外の変数を隠しましたが、Go ではただの `{}` ブロックでも同じことが起きます。🟡 「`:=` は新しい変数を作る」ことを意識して、どの変数が見えているか読み取れるようになりましょう。

Python ではこう書いた:

```python
x = 1
def f():
    x = 2  # 関数の中だけの別の x
f()
print(x)  # 1
```

Go ではこう書く:

```go
x := 1
{
	x := 2 // ブロックの中だけの別の x
	fmt.Println(x) // 2
}
fmt.Println(x) // 1
```

## ch03 パッケージ変数（global 文はない）

関数の**外**で宣言した変数を**パッケージ変数**といい、同じパッケージのどの関数からも読み書きできます。Python では関数の中から書き換えるときに `global` 文が必要でしたが、**Go に `global` や `nonlocal` はありません**。関数の外に書けば、宣言なしでそのまま読み書きできます。ただし、どこからでも変えられる変数は追いかけるのが大変なので、基本は引数と戻り値で渡し、パッケージ変数は設定値など最小限にとどめます。🟡

Python ではこう書いた:

```python
count = 0

def add():
    global count  # global 宣言が必要
    count += 1
```

Go ではこう書く:

```go
var count int // 関数の外に書く（パッケージ変数）

func add() {
	count++ // global なしで書き換えられる
}
```

## ch04 := が作る意図しない新変数

`:=` は代入ではなく**宣言**です。そのため内側のブロックで外側と同じ名前に `:=` を使うと、意図せず新しい変数を作ってシャドーイングしてしまいます。実務での典型が `if v, err := f(); err == nil {` の形で、ここで作った `v` や `err` は **if の外では使えません**。Python にはない、`:=` と `=` の使い分けから生まれる実務の落とし穴です。外に残したいときは先に宣言して `=` で代入します。🟡 この違いは Go を書く限りずっとついて回るので、理屈を押さえましょう。

Python ではこう書いた:

```python
n = 0
if True:
    n = int("42")  # 代入はいつも同じ n を指す
print(n)  # 42
```

Go ではこう書く:

```go
n := 0
if true {
	n := 42 // := だと新しい n。外の n は 0 のまま
	_ = n
}
// 外の n に入れたいなら = で代入する
```
